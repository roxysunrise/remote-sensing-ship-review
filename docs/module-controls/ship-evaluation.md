# 船舶 OBB 对比评估

负责人为 A 方。工具复用当前船舶检测算法及多边形 IoU，对同一批有标注影像运行整图推理和切片推理。两种模式使用相同权重、船舶类别、网络输入大小、置信度和模型内 NMS 参数。切片模式另记录切片尺寸、步长和跨片合并阈值。该入口独立运行，不改变业务 API。

## 准备评估清单

按 [算法模块说明](../../algorithm/README.md) 安装依赖并取得可信本地权重。以下是清单格式示例，坐标是原图像素，顺序可由工具归一化。每张图都须完整标注船舶，确认无船时显式填空数组。

```json
{
  "source": "已获授权的港口影像及标注版本",
  "split": "固定验收集名称或版本号",
  "independence": "记录与训练、调参集比对的范围、方法和结果",
  "samples": [
    {
      "image": "port-with-ships.png",
      "ships": [[[210, 92], [241, 106], [236, 117], [205, 103]]]
    },
    {"image": "verified-empty.png", "ships": []}
  ]
}
```

影像路径相对于清单目录。重复路径或内容、缺少标注列表、越界或不合法的四边形会报错并以状态 2 退出。工具支持现有 RGB PNG/JPEG 输入和切片模块的像素限制。评估的整图路径使用内存图像入口，允许与切片输入相同的像素上限，便于比较同一张大图。正式验收时由 A 方核实数据授权和独立性，排除与训练、调参或演示影像重叠的同源裁片。填写来源字段只会写入证据报告，工具无法判断数据独立性。

## 执行与读数

在仓库根目录运行，报告、影像和权重保存在忽略目录或外部存储中。

```powershell
python -m scripts.evaluate_ship_obb var/harbor-acceptance/manifest.json --weights var/models/best.pt --device cpu --imgsz 1024 --tile-size 1024 --stride 512 --merge-iou 0.1 --match-iou 0.5 > var/harbor-acceptance/report.json
```

结果包含数据来源声明、清单与影像哈希、权重和运行环境、参数、逐图及全量计数。预测按置信度降序，匹配剩余标签中满足阈值且 IoU 最大的一项。只能匹配已占用标签的预测计作重复误报。全量 Precision 和 Recall 按 TP、FP 和 FN 总和计算，分母为零时返回 `null`。结果是固定置信度和匹配 IoU 的读数。正式验收可事先按小船、密集港口和切片边缘分组，使用各组清单分别运行。耗时以整个推理调用为口径，包含解码和切片合并，切片入口另含内部文件指纹开销。第一幅图额外进行一次整图预热，预热不计时。峰值内存和跨硬件稳定性须另测。
