## 3. 本轮修掉的缺陷

### 3.1 P0：真实任务跑完后草稿恒为空

| 项 | 内容 |
|---|---|
| 现象 | 任务 `done`、`result.count=13`、`/versions/v0` 有 13 个框，但 `GET /tasks/{id}/draft` 返回 `detections=[]` |
| 复现 | 真实权重下 100%：`result.count=13 / v0.detections=13 / draft.detections=0` |
| 根因 | `jobs.py::_ensure_v0` 发布 v0 后顺手 `INSERT OR IGNORE INTO draft_state`；而 `api.py::_ensure_draft` 的早退条件就是"draft_state 存在"，于是从不把 v0 的框灌进 `draft_detections` |
| 影响 | 复核工作台打开是空画布；且首次提交会把空草稿当成"删除全部 13 个框"提交，静默产生一个清空结果的版本（实测 v1 的 `detections` 为 `[]`） |
| 修复 | 删除 `jobs.py` 里那行 INSERT，草稿统一由 `_ensure_draft` 懒创建；并把填充逻辑抽成 `_fill_draft`。额外加自愈：`draft_state` 存在但没有内容、且基线版本非空时补齐（老库/异常路径不再永久空） |
| 反证 | `git stash` 回退修复后跑 `test_task_lifecycle_end_to_end`：`AssertionError: 0 != 1`，用例确实能抓住这个 bug |
| 回归 | 新增 3 项不依赖权重的用例（正常创建 / 空 state 补齐 / 空基线不造框），全套 77 项通过 |

这条路径此前一直没被发现，是因为 `test_task_lifecycle_end_to_end` 标了 `skipUnless(HAS_WEIGHTS)`，
而本地没有 `best.pt`，用例被静默跳过——**历史上"17 项通过（含真实 CPU 推理）"的说法不成立**。

### 3.2 补 `GET /projects/{project_id}/images`

联调时发现工作台展示"影像数量 1 幅 harbor.png"，而后端实际有 6 个影像。
原因是没有任何端点能列出项目影像，前端只能用内置 `SCENE` 常量兜底。

新增端点（`api.py`）：`GET /projects/{project_id}/images` → `{project_id, total, items[]}`，
`items` 复用 `_image_payload`（含 `file_url` / `preview_url` / `sha256` / 尺寸）。
成员校验复用 `_member`，跨项目 403；补 1 项测试。

## 4. 联调暴露、但未在 A 侧处理的问题（B 侧）

1. `index.html:63` 的"演示数据"徽章是硬编码 `<span class="badge demo">`，`apiMode` 已是 `http` 仍显示，
   演示和验收时会被误认为页面在跑模拟数据。
2. 工作台影像卡片走 `app.js` 的 `SCENE` 兜底（`app.js:1336-1338`），所以显示的 `harbor.png / 1 幅 / sha 07b4c0ad…`
   与后端 6 个影像不符。接入 §3.2 的新端点即可解决。
3. `detect-config.js` 的 `baseUrl: ''` 表示同源；本轮前端跑在 `:8765`、后端在 `:8000`，
   必须改成绝对地址才能跨域。生产用同源反代时无影响，需要 B 侧确认部署形态。
